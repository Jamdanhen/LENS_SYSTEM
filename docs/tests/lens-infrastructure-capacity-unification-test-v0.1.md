# LENS Infrastructure Capacity Unification Test

Version: 0.1  
Status: Strong Conditional Pass; No Final Capacity Name Adopted  
Date: 2026-09-01

---

## Purpose

This test evaluates whether `Infrastructure` can name the Capacity governing
Expressions carried through Leverage without creating a second, incompatible
meaning for the existing LENS Infrastructure term.

Current Leverage Derived Attributes:

```text
Assets
Network
Authority
Reputation
Background
```

The test does not adopt Infrastructure as the final Capacity name.

---

## Existing Infrastructure Doctrine Held Constant

Current definition:

```text
Infrastructure is any persistent source, route, storehouse, support structure,
or denial point for Lenses.
```

Current possible functions:

```text
grant Resonance;
impose Dissonance;
deny Access;
store or route capacity;
stabilize recovery;
support return after defeat;
or change what actions are possible.
```

Current core rule:

```text
Location alone is not enough.

Usable Access, control, compatibility, permission, repair, or routing is
required to benefit from Infrastructure.
```

Current examples already include:

```text
bases
networks
strongholds
institutions
supply chains
social legitimacy
magical sites
ship systems
ecosystems
artifacts
```

This definition is broader than buildings or machinery.

## Proposed Unification

The candidate is not based upon two unrelated meanings.

It proposes one general concept with two subjects:

```text
Personal Infrastructure

The persistent material, relational, institutional, reputational, and
historical support structure through which a Character exercises Leverage.


External Infrastructure

A persistent source, route, storehouse, support structure, control system, or
denial point existing outside the Character.
```

Candidate Capacity definition:

```text
Infrastructure Capacity is the limit of relevant Condition pressure a
Character's personal Infrastructure can bear before Leverage function is lost
or exhausted.
```

This definition is a test candidate, not adopted doctrine.

not become Infrastructure or another modifier.

```text

It should not cause every formative event to be described as Infrastructure.
```

## Test 6: Isolated Character

Scenario:

```text
A hermit possesses a fortified shelter, tools, stored food, medicine, and a
hidden reserve of valuable material.

The Character has almost no active Network, Authority, or Reputation.
```

Result:

```text
Assets remain personal Infrastructure.

Infrastructure does not require other people or formal institutions.

The Character may possess Infrastructure Capacity even when most Leverage
Derived Attributes are low, unranked, inaccessible, or currently irrelevant.
```

Capacity measures how much relevant pressure the locus can bear. It does not
measure the amount of Infrastructure possessed. Leverage and its Derived
Attributes measure developed capability.

Finding:

```text
STRONG PASS
```

## Test 7: Personal and External Subjects

Scenario:

```text
A Character relies upon a Royal Workshop.

The Workshop is corrupted and becomes unusable.
```

External state:

```text
Workshop Corrupted 4

Subject: Royal Workshop
Type: External Infrastructure Condition
Result: workshop functions and routes are disrupted
```

Character state:

```text
Workshop Access Closed

Subject: Character
Type: Access consequence
Result: the Character cannot benefit from the Workshop
```

The Workshop Condition does not automatically become four levels of the
Character's Infrastructure Load.

A hostile Expression may separately impose:

```text
Institutional Support Severed 2

Subject: Character
Capacity: Infrastructure
Primary scope: Assets, Network, or Authority according to the fiction
```

That is a separate effect upon a separate subject.

Finding:

```text
PASS WITH REQUIRED SUBJECT LABELING

Personal and external Infrastructure can share one concept if every Condition
identifies its subject. The system must not copy external damage into personal
Load automatically.
```

## Test 8: External Infrastructure Supporting Other Attributes

Scenario:

```text
A magical site supports a Psyche-carried ritual.

A ship system supports a Mobility-carried maneuver.

An artifact supports a Might-carried strike.
```

These are all external Infrastructure.

They do not become Leverage Expressions merely because the third Capacity may
be named Infrastructure.

Correct routing:

```text
The declared Expression identifies its carrying Attribute.

The external Infrastructure contributes only when applicable.

Damage to that Infrastructure affects its own functions or Access.

The Character gains Infrastructure Load only when a distinct effect pressures
the Character's personal Leverage structure.
```

Finding:

```text
PASS WITH TERMINOLOGY PRESSURE

The shared word does not require shared routing, but the distinction must be
prominent. Infrastructure is a kind of persistent Lens structure;
Infrastructure Capacity would be the Capacity of one subject's personal
Leverage structure.
```

## Test 10: Access, Load, and Double Counting

At Infrastructure Load 5:

```text
The Character's Infrastructure Function Band is 75%.

Accounts Frozen determines which Assets Access is Conditional or Closed.

Publicly Disgraced determines which Reputation Access is Conditional.
```

Incorrect resolution:

```text
Leverage Expression
x 0.75 Infrastructure Function Band
/ Accounts Frozen again
/ Publicly Disgraced again
```

Correct resolution:

```text
Leverage Expression
x 0.75 Infrastructure Function Band
x other distinct Resonance
/ other distinct Dissonance
= Final Rating
```

The Conditions remain important because they identify source, scope, Access,
recovery, and counterplay. Their numerical Load effect is not applied twice.

Finding:

```text
STRONG PASS
```

## Test 11: Recovery and Repair

External repair:

```text
Repair the Royal Workshop.

Target: Royal Workshop
Effect: remove matching Workshop Corrupted levels
```

Personal recovery:

```text
Restore the Character's suspended license.

Target: Character
Effect: remove matching License Suspended levels and restore matching Access
```

One Expression may address both only if its declared effect genuinely reaches
both subjects. Generated Effect Levels remain conserved and must be allocated
to the effects actually produced.

Finding:

```text
PASS

The existing matching-recovery and effect-conservation rules distinguish
repairing external Infrastructure from restoring personal Infrastructure.
```

## Optional-to-Universal Status Test

Current Infrastructure doctrine calls Infrastructure an optional
setting-facing feature.

Infrastructure Capacity would be part of the universal Character architecture.

Those statuses cannot remain unchanged without explanation.

Two possible interpretations were tested:

```text
MODEL A: TWO UNRELATED TERMS

Infrastructure Capacity is only a name for the Leverage Capacity.
External Infrastructure remains a separate optional feature.

RESULT: FAIL

The same capitalized term would perform unrelated jobs.


MODEL B: ONE GENERALIZED CONCEPT

Infrastructure is a universal persistent-support concept.

Every Character possesses personal Infrastructure expressed through Leverage.

Settings may additionally provide external Infrastructure such as strongholds,
workshops, ship systems, magical sites, and organizations.

RESULT: PASS
```

Model B is the only viable route to adoption.

It would change the status of generic Infrastructure from an optional concept
to a universal structural concept whose external implementations remain
optional.

That is a real architecture decision, not a cosmetic naming decision.

## Overall Finding

```text
STRONG CONDITIONAL PASS

Infrastructure survives the complete Leverage Derived Attribute scope test.

Infrastructure Capacity, Infrastructure Load, Infrastructure Function Band,
and Infrastructure Condition all produce strong rules language.

The existing Infrastructure definition is already broad enough to support
material, relational, institutional, reputational, and historical structures.

Personal and external Infrastructure remain distinguishable through subject,
scope, Access, and effect.

The one-ledger, applicability, distinct-contribution, effect-conservation, and
matching-recovery rules remain sufficient.

No separate subsystem is required.

However, Infrastructure cannot be adopted merely as a Capacity label while the
existing term remains an optional, unrelated setting feature.

Adoption requires one generalized Infrastructure doctrine with personal and
external applications.
```

## Decision Produced by the Test

The naming question has exposed a larger architecture question:

```text
Should Infrastructure become a universal LENS concept describing persistent
support structures, with every Character possessing personal Infrastructure
through Leverage and settings optionally supplying external Infrastructure?
```

If yes:

```text
Infrastructure becomes the strongest tested name for the third Capacity.
```

If no:

```text
Infrastructure should be rejected as the Capacity name despite its strong
grammar and scope.
```
