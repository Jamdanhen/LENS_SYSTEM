# LENS Background Capacity Third-Locus Test

Version: 0.1  
Status: Partially Superseded Working Architecture Test  
Date: 2026-08-31

> Supersession note: The later Leverage fifth-Attribute test preserves the
> third-Capacity concept but gives its Function Band a narrower target:
> Expressions carried through Leverage. References in this file to six
> Background umbrellas or a mandatory Background HOLT are retained as test
> history rather than the current leading architecture.

---

## Purpose

This test evaluates whether background and worldly pressure can use the
existing Capacity, Load, Condition, Function Band, Access, Accepted
Consequence, and Recovery architecture as a third functional locus.

The candidate loci are:

```text
Physical Capacity
Mental Capacity
Background Capacity
```

The test does not adopt final background construction costs, HOLT ratings,
condition values, Accepted Consequence exchange values, or Campaign Profile
numbers.

---

## Working Test Controls

The following controls were supplied for this test:

```text
1. Total Background Load reduces every Background HOLT Expression.

2. Specific Conditions may alter Access through the same procedures used for
   Physical and Mental Conditions.

3. The same Condition Levels are not counted once through a Function Band and
   again as separate Dissonance in the same calculation.

4. Every Character in the same Campaign Profile begins with equal Background
   Capacity.

5. Background Capacity may vary by Campaign Profile.

6. Additional Background Capacity may potentially be purchased by accepting
   additional Exposures or Limitations. The exchange value is unresolved.

7. One master Condition Ledger must remain sufficient.

8. Background Load does not automatically create Physical or Mental Load.

9. Physical, Mental, and Background pressure may interact only when the
   fiction creates the additional effect or a Character accepts a consequence
   that transfers or creates pressure in another locus.
```

Status:

```text
WORKING TEST CONTROLS
NOT FINAL DOCTRINE
```

## Candidate Architecture

For this test, Background Capacity means:

```text
How much accumulated pressure against the Character's worldly identity,
resources, relationships, standing, profession, disposition, and origin can
be borne before Background function is lost or exhausted.
```

Background Load means:

```text
The sum of current Condition Levels assigned to the Background locus.
```

Background Conditions name the composition of that Load.

Examples include:

```text
Assets Frozen
Contacts Compromised
Publicly Disgraced
License Suspended
Debt Called In
Broken Promise
Organization Hostile
Legacy Contested
```

Background Function Bands use the current shared model:

```text
Background Load 0-2  = 100%
Background Load 3-5  = 75%
Background Load 6-7  = 50%
Background Load 8-9  = 25%
Background Load 10+  = loss or exhaustion of Background function
```

The resulting Function Band applies to every Background HOLT Expression.

Specific Conditions still determine:

```text
what is fictionally wrong;
which permissions or resources remain available;
whether Access is Open, Conditional, or Closed;
what recovery or counter is required;
and whether the event also creates a separate Physical or Mental Condition.
```

## One-Ledger Representation

Illustrative ledger:

```text
Condition             Levels  Capacity     Scope          Access Effect
Assets Frozen         3       Background   Resources      Conditional or Closed
Broken Promise        2       Background   Connections    Conditional
Publicly Disgraced    1       Background   Standing       Conditional
Wounded               2       Physical     Physical       None by default
Shaken                1       Mental       Mental         None by default
```

Derived views:

```text
Background Load = 3 + 2 + 1 = 6
Physical Load   = 2
Mental Load     = 1

Background Function Band = 50%
Physical Function Band   = 100%
Mental Function Band     = 100%
```

The conditions remain in one ledger. Capacity views are queries, not separate
condition tracks.

Finding:

```text
PASS

One master ledger remains sufficient when every entry records its Capacity
locus, relevant scope, Access effect, and recovery or counter.
```

## Test 1: Ordinary Background Use

Assume a Character possesses the provisional Background HOLT:

```text
Wealthy Noble
```

The Character attempts to secure temporary lodging through established
Resources and Standing.

Starting state:

```text
Background Load:          0
Background Function Band: 100%
```

The Character may use the prepared Background Expression normally.

Ordinary use does not automatically create Load. A Background HOLT is not a
consumable resource merely because it is invoked.

Load may arise from:

```text
consequential failure;
hostile opposition;
overextension;
depletion established by the fiction;
broken obligations;
loss of Access;
or another persistent consequence.
```

Finding:

```text
PASS

The candidate does not require a universal use counter.
```

## Test 2: Global Background Pressure

Diagnostic prepared Background Expression Ratings:

```text
Resources Expression:   80
Connections Expression: 60
Standing Expression:    40
```

These values are test controls only.

An opponent freezes the Character's accounts and imposes:

```text
Assets Frozen 3 [Background: Resources]
```

Result:

```text
Background Load:          3
Background Function Band: 75%

Resources Expression:   80 x 0.75 = 60
Connections Expression: 60 x 0.75 = 45
Standing Expression:    40 x 0.75 = 30
```

The Resources Condition pressures every Background Expression through the
shared Background Load. It also has a more specific fictional consequence:
direct Access to the frozen accounts may be Conditional or Closed.

The Character may still attempt a different route, such as obtaining credit
through Connections or asserting Standing, but does so through the reduced
Background Function Band.

Finding:

```text
PASS

One Background Load can create broad pressure without creating a separate
Resources, Connections, Standing, Profession, Disposition, or Origin track.
```

## Test 3: Function Band Transitions

Additional Conditions accumulate:

```text
Assets Frozen       3
Broken Promise      2
Publicly Disgraced  1
```

Progression:

```text
Load 3: Assets Frozen
Function Band: 75%

Load 5: Assets Frozen + Broken Promise
Function Band: 75%

Load 6: Assets Frozen + Broken Promise + Publicly Disgraced
Function Band: 50%
```

Using the same diagnostic Expressions:

```text
Resources Expression:   80 x 0.50 = 40
Connections Expression: 60 x 0.50 = 30
Standing Expression:    40 x 0.50 = 20
```

Finding:

```text
PASS

The existing Function Bands produce visible deterioration without requiring
recalculation at every Condition Level.
```

## Test 4: Double-Counting Control

At Background Load 6, the Background Function Band is already 50%.

The correct calculation is:

```text
Prepared Background Expression
x 0.50 Background Function Band
x other current Resonance
/ other current Dissonance
= Final Rating
```

The incorrect calculation is:

```text
Prepared Background Expression
x 0.50 Background Function Band
then reduced again by the same six Background Condition Levels
```

The Conditions still matter individually because they establish narrative
scope, Access, recovery, and vulnerability. They do not impose the same
numerical loss twice.

Independent resistance may still apply normally.

Examples:

```text
active opposition from a hostile banker;
Difficulty created by an unusually resistant institution;
environmental or legal restrictions not already represented in Background
Load;
or another relevant Dissonance that has not already produced the Function
Band being applied.
```

Finding:

```text
PASS

The existing no-double-counting rule remains sufficient.
```

## Test 5: Specific Access Effects

Background Load creates broad functional pressure.

Specific Conditions determine what remains accessible.

Examples:

```text
Assets Frozen

The Wealthy Noble HOLT remains present.

Liquid accounts may have Closed Access.
Credit secured through collateral may have Conditional Access.
Unrelated property may retain Open Access.

License Suspended

The Profession remains part of the Character.

Practicing under the license may have Closed Access.
Offering informal knowledge may retain Open Access.
Institutional records may have Conditional Access.

Contacts Compromised

The Connections remain part of the Character's history and identity.

Contacting the compromised network may have Conditional Access.
A particular contact who has defected may have Closed Access.
An unrelated personal relationship may retain Open Access.
```

Finding:

```text
PASS

Background Conditions can use the existing Access model without erasing the
HOLT or inventing a Background-specific permission rule.
```

## Test 6: Capacity Independence

Starting ledger:

```text
Assets Frozen       3 [Background]
Broken Promise      2 [Background]
Publicly Disgraced  1 [Background]
```

Derived result:

```text
Background Load: 6 = 50% Background Function Band
Physical Load:   0 = 100% Physical Function Band
Mental Load:     0 = 100% Mental Function Band
```

The Character's finances, relationships, and standing are under severe
pressure. The Character is not automatically wounded, exhausted, terrified,
or mentally impaired.

Finding:

```text
PASS

The three Capacities remain independent by default.
```

## Test 7: Fictional Cross-Capacity Effects

The same conflict may produce consequences in more than one locus when the
fiction actually creates them.

Example:

```text
A creditor calls in a debt.

Debt Called In 3 [Background]

The creditor later sends enforcers who injure the Character.

Wounded 2 [Physical]
```

The debt does not convert automatically into Physical Load. The assault is a
new fictional event that creates a Physical Condition.

Another example:

```text
A public scandal imposes Publicly Disgraced 3 [Background].

The Character internalizes the crisis and becomes Shaken 2 [Mental].
```

Shaken is recorded only if the fiction and resolution establish that Mental
effect. Public disgrace does not automatically reduce Mental Capacity.

Finding:

```text
PASS

Cross-Capacity interaction requires an explicit fictional and mechanical
cause. It is not automatic spillover.
```

## Test 8: Accepted Consequence Across Capacities

At severe Background Load, a Character may accept a meaningful persistent
loss or restriction to remove enough Background Load to continue functioning.

Possible same-locus consequence:

```text
Liquidate the ancestral estate.

Remove the agreed amount of immediate Background Load.
Close Access to the estate and its associated Resources until it is restored
or reacquired through the fiction.
```

Possible cross-locus consequence:

```text
Accept a severe beating from the creditor's enforcers in exchange for ending
the immediate collection pressure.

Remove the agreed amount of Background Load.
Record a named Physical Condition and its levels.
```

Possible Mental consequence:

```text
Maintain the public role by accepting an obsessive or destabilizing burden.

Remove the agreed amount of Background Load.
Record a named Mental Condition and its levels.
```

The exchange does not occur merely because two tracks exist. The accepted
result must make narrative sense and must be persistent enough to constitute a
real consequence.

Finding:

```text
CONDITIONAL PASS

The architecture supports same-locus and cross-locus consequences. The exact
Load removed, Condition Levels imposed, and equivalence between different
consequences remain unresolved and require numerical testing.
```

## Test 9: Background Function at Load 10

At Background Load 10 or more:

```text
Background function is lost or exhausted.
```

This does not mean:

```text
the Character is physically incapacitated;
the Character is mentally incapacitated;
the Character's history is erased;
every Background Access state becomes permanently Closed;
or every Background relationship ceases to exist.
```

The Load composition determines what the loss of function means.

Examples:

```text
Resources pressure may produce insolvency, seizure, or inability to mobilize
assets.

Connections pressure may produce isolation, network collapse, or inability to
call upon relationships.

Standing pressure may produce disgrace, loss of authority, or inability to
exercise recognized status.

Profession pressure may produce suspension, institutional exclusion, or
inability to practice.
```

The Background HOLT remains a stable Character truth unless the fiction
actually changes it. Load 10 suppresses Background function; it does not
silently rewrite the Character.

Finding:

```text
PASS

The same Load-10 principle can produce a different narrative result for each
Capacity without a different resolution system.
```

## Test 10: Recovery

Background Conditions use the shared Recovery procedure.

Examples:

```text
Assets Frozen
Counter through legal relief, repayment, negotiation, proof, institutional
intervention, or another appropriate method.

Broken Promise
Counter through restitution, reconciliation, fulfillment, or rebuilding
trust.

Publicly Disgraced
Counter through exoneration, public service, evidence, political repair, or
acceptance by the relevant community.

License Suspended
Counter through review, retraining, restitution, appeal, or satisfaction of
the suspending condition.
```

Current Recovery testing remains:

```text
Success removes one matching Condition Level.

Each complete 10 points of Successful Margin removes one additional matching
Condition Level.
```

Recovery must answer the named Condition. An unrelated success does not erase
Background Load.

Finding:

```text
PASS

No Background-specific recovery subsystem is required.
```

## Test 11: Disposition and Locus Routing

Disposition creates a useful boundary test because one source may produce
different kinds of consequences.

Example:

```text
Persistent gambling behavior may establish:

Craving 2        [Mental]
Gambling Debt 3  [Background: Resources]
Broken Trust 2   [Background: Connections]
Wounded 1        [Physical], but only if violence actually occurs
```

The behavior does not create one universal penalty applied everywhere.

Each established consequence enters the master ledger once, under the locus
and scope its fiction supports.

Finding:

```text
PASS

The third Capacity clarifies the difference between internal pressure and the
worldly consequences of a Character truth.
```

## Test 12: Equal Capacity and Campaign Profiles

Within one Campaign Profile:

```text
Every starting Character receives the same Background Capacity.
```

A wealthy noble and an isolated drifter may have very different Background
HOLTs, ratings, permissions, and vulnerabilities. Neither receives additional
Background Capacity merely because one background is broader or more
powerful.

The Campaign Profile determines the baseline Capacity used by that game.

This allows a grounded social-drama campaign, a heroic fantasy campaign, and a
world-spanning political campaign to set different Background endurance
without changing the underlying rule.

Possible Character-specific improvement:

```text
Accept additional Exposures or Limitations in exchange for greater Background
Capacity.
```

Finding:

```text
CONDITIONAL PASS

Equal baseline Capacity is coherent. Campaign Profile variation is coherent.
The cost and compensation relationship for Character-specific improvement is
not yet known and must not be assigned arbitrarily.
```

## Consolidated Findings

```text
PASS
Background can function as a third Capacity locus.

PASS
Total Background Load can reduce every Background HOLT Expression without
creating separate Load tracks for each umbrella or HOLT.

PASS
Specific Conditions can still alter Access, scope, recovery, and vulnerability.

PASS
The existing no-double-counting rule prevents Function Band loss from being
applied again as the same Dissonance.

PASS
Physical, Mental, and Background Capacity can remain independent by default.

PASS
Explicit events and Accepted Consequences can create cross-Capacity effects.

PASS
One master Condition Ledger remains sufficient.

PASS
The existing Recovery procedure can answer Background Conditions.

CONDITIONAL PASS
Equal Background Capacity and Campaign Profile variation work conceptually,
but exact baseline variations are not selected.

CONDITIONAL PASS
Exposures or Limitations may potentially purchase additional Background
Capacity, but the exchange rate and abuse controls are unresolved.
```

## Primary Design Finding

```text
Background Capacity does not require a separate background game.

It extends the existing universal architecture into a third locus:

Capacity defines the limit.

Load records accumulated pressure.

Conditions name the composition of that pressure.

Function Bands reduce the affected class of Expressions.

Access records what remains available.

Accepted Consequences exchange immediate pressure for persistent loss or
restriction.

Recovery answers the named Condition through the fiction.
```

## Unresolved Decisions

```text
1. What is the final name of the third Capacity locus?

2. Does Background become the formal HOLD name, or is it only the current
   working label?

3. Are Resources, Connections, Standing, Profession, Disposition, and Origin
   the final Background umbrellas?

4. How are starting Background HOLT and umbrella ratings purchased?

5. How much Background Load does a successful hostile Expression impose?

6. How much Load may an Accepted Consequence remove?

7. How are cross-Capacity consequences valued?

8. How much additional Background Capacity may an Exposure or Limitation
   purchase?

9. What exact Background Capacity values do different Campaign Profiles use?

10. What procedures distinguish temporary depletion from a lasting change to
    a stable Background truth?
```
